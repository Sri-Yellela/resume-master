# Outsider walk — every endpoint as a stranger sees it (A55)

Generated by `node scripts/outsiderWalk.mjs` (in-process, the real app, a freshly minted token for a
client called `outsider`, **no model key** — nothing spent). Re-run it after any change to an error
body. A live walk against the deployed service is `npm run verify:live` with a token.

## What the walk found (2026-10-02) and what changed

| Finding | Fix |
|---|---|
| **401 `unauthenticated` said nothing** — a stranger without a token had no way to learn what to send or how to get one | It now says: send `Authorization: Bearer rmk_<client>.<secret>`; tokens are issued by the operator on request (no self-serve API sign-up yet); the free tools need no token on the site. It never says what was wrong with a presented token |
| `invalid_json`, `payload_too_large`, `not_found`, `limit_exceeded` were codes with no sentence | Each now carries a `message` (the contract's `Error.message` was already optional — no version change) |
| Limits were off with no way to turn them on short of a code change | `RM_LIMITS_PER_DAY="acme=50,*=200"` caps model-backed calls per client per UTC day; unset = off (unchanged decision); `draft` is unlimited unless named |

## ⛔ The blocker is the TOKEN POLICY, not the endpoints — owner (O16c)

Every endpoint above answers legibly. What a stranger still cannot do is **get in**: API tokens are
minted by hand (`scripts/mintClientToken.mjs`). The choices — self-serve issuance tied to a site
account (A57 made accounts exist), an anonymous tier for the zero-cost tools over the API/MCP, or
keys by request — are the owner's. Until then: the site's ATS check and formatting ARE public and
anonymous (A54, per-IP rate-limited); the API and MCP are by-request.
